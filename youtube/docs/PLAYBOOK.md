## 2. 단계별 방법

### 1단계 · 주제와 각도

1. **주제 후보**: [`STATUS.md`](STATUS.md)의 '다음 편' → 없으면 [`03_roadmap_100.md`](03_roadmap_100.md) 순서. 큰 뉴스가 있으면 시사 해설 편을 끼워 넣을 수 있습니다(EP.09가 그 예, 번호는 그냥 다음 번호).
2. **수요 확인** (키가 있을 때):
   ```bash
   python -m studio.benchmark topic "스태그플레이션" "오일쇼크"
   ```
   최근 1년 그 키워드의 상위 영상이 나옵니다. **구독자 대비 조회수(배수)가 3 이상인 얼굴 없는 해설 채널**의 영상이 있는지, 그 영상이 어떤 각도(사건 이야기·생활 질문·목록)로 들어갔는지 봅니다.
3. **각도 정하기** — 가장 중요한 결정입니다. 2026-11 벤치마크의 결론:
   - 용어 이름을 앞세운 영상("스태그플레이션의 모든 것")은 전문가·방송 채널과 경쟁하게 되어 불리합니다.
   - 같은 지식을 **사건·인물·숫자 하나를 줄거리로 삼은 이야기**로 포장하면 얼굴 없는 채널에도 기회가 있습니다(예: 대공황 이야기로 디플레이션을 설명).
   - 그래서 한 편마다 **줄거리 하나**(실제 사건, 한 사람의 하루, 숫자 하나의 여행)를 정하고, 개념 설명은 그 줄거리를 따라가며 합니다.
4. **세 갈래를 번갈아**: ① 경제사 사건 다큐 ② 돈의 원리·생활 금융 ③ 지금 이슈 해설. 어느 갈래가 우리 채널에서 통하는지 아직 모릅니다. 성적은 [`STATUS.md`](STATUS.md)에 기록합니다.
5. 기획서 2번 칸에 조회 결과와 고른 각도, 따라 하지 않을 것을 적습니다.

### 2단계 · 제목 A/B/C와 썸네일 A/B/C

**제목**은 서로 다른 '틀' 세 개를 씁니다(같은 영상에 붙여 유튜브 스튜디오의 '테스트 및 비교'로 비교).

| 안 | 틀 | 예 |
|---|---|---|
| A | 이야기형: `궁금증 한 문장 \| 사건·대상 + 진짜 이유` | 물건은 넘치는데 왜 모두 가난해졌을까 \| 1929 대공황의 진짜 이유 |
| B | 목록형 `대상 + N가지` 또는 `"인용 한마디" + 대상이 ~한 이유` | 금융자산 10억 생기면 실제로 벌어지는 일 6가지 |
| C | 기존형: `초등학생도 이해하는 ~의 모든 것 ({MIN}분 총정리)` | 초등학생도 이해하는 양적완화와 긴축의 모든 것 (30분 총정리) |

- 45자 안팎이 좋고 60자를 넘기지 않습니다(잘 된 영상 중앙값 44자).
- 세 제목의 앞부분은 서로 달라야 하고, 각 제목이 던진 질문은 **영상 안에서 실제로 답해야** 합니다.
- 분 표기는 `{MIN}` 으로 쓰면 실제 길이로 채워집니다. 숫자를 직접 쓰지 않습니다.
- **쓰지 않는 말**: 충격·소름·경악·대참사·떡상·대박·긴급·속보·무조건·보장·100%·"지금 사야"·사세요·파세요·추천주. (점검이 오류로 막습니다)
- **조심할 말**: 폭락·붕괴·몰락·파산 — 지나간 사건을 사실대로 부를 때만. 앞날을 예고하는 뜻("○○ 온다")으로는 쓰지 않습니다.

**썸네일**은 제목 A/B/C와 짝입니다(`META["thumbnails"]`).
- 기본 구도는 `scene`(밝은 하늘·도시·지폐·큰 화살표 + 큰 캐릭터). 세 장의 배경색(`scene`: city·dawn·gold·mint·rose)을 서로 다르게.
- 글자 덩어리는 3개까지: 위 작은 인용(`quote`), 큰 숫자·낱말 하나(`num`, 6자 안팎), 아래 두 줄(`top` 흰색, `main` 노란색, 12자 안팎).
- 숫자는 사실 확인표에 있는 것만. 쓰지 않는 말은 제목과 같습니다.
- `stills` 를 만들면 `out/sheets/thumbs_0.jpg` 에 세 장이 나란히 나옵니다. **작게 봐도 한눈에 읽히는지** 확인합니다.
- 구도·옵션 전체는 [`VISUALS.md`](VISUALS.md) 6장, 연구 내용은 `learning/thumbnail_study.md`.

### 3단계 · 사실 확인 (대본보다 먼저)

영상의 신뢰와 정책 안전이 여기서 결정됩니다. **대본을 쓰기 전에** `01_plan.md` 의 사실 확인표를 채웁니다.

1. 영상에 넣을 **모든 숫자·날짜·인용**을 한 줄씩 적습니다.
2. 지금 값(금리·물가·성장률·환율·주가·기관 발표)은 **기억으로 쓰지 않습니다.** 웹 검색으로 찾고, 가능하면 발표 기관의 원문(한국은행·통계 기관·기획재정부·미국 연준·노동통계국 등의 보도자료나 보고서)을 직접 열어 숫자를 확인합니다.
3. 표시:
   - ✅ = 원문에서 그 숫자를 직접 봤다 (어느 문서의 어느 날짜 것인지 적기)
   - ⚠️ = 검색 요약·보도·기억에만 의존했다 → 영상에서는 **"약", "보도에 따르면", "일반적으로 알려진"** 으로 완충하거나 뺍니다
   - 가정 = 이해를 돕기 위해 만든 숫자 → 화면이나 말에 "가정"이라고 밝히고 설명란 출처에도 적습니다
4. **기준일**을 정해 세 곳에 넣습니다: 설명란 첫 줄(`※ ○월 ○일 기준`), 아웃트로 내레이션, 고정 댓글.
5. 확인이 안 되는 내용은 넣지 않습니다. 그럴듯한 숫자를 만들어 넣는 것이 이 채널에서 가장 큰 잘못입니다.
6. 논쟁 중인 주제는 "해석이 갈립니다"라고 하고 양쪽 주장을 같은 무게로 소개합니다.
7. 보고할 때 ⚠️ 항목이 무엇인지 채널 주인에게 알립니다(업로드 페이지의 '올리기 전 확인'에도 자동으로 나옵니다).

### 4단계 · 대본 (`script.py`)

`python -m studio.ep new <번호> <영어이름>` 이 만든 `script.py` 는 그대로 실행되는 틀입니다. `○` 가 남아 있으면 점검이 막습니다.
**막히면 `episodes/ep13_qe_qt/script.py` 의 같은 자리를 보세요.** 그 파일이 이 채널의 표준 예시입니다.

#### 4-1. 분량 기준 (30분 기준, EP.13 실측)

| 항목 | 기준 |
|---|---|
| 길이 | 30분 안팎 (채널 주인 요청. 내용이 충분하면 더 길어도 좋음. 다큐형은 40분 이상도 시험) |
| 내레이션 | 약 1만 3천 자 (1분에 약 450자) |
| 문장 | 약 165개 · 한 문장 60~120자 (평균 80자) |
| 장면 | 70~80개 · 장면당 2~3문장, 20~35초 (55초를 넘기지 않기) |
| 파트 | 인트로 + PART 6~7개 + 정리 (파트당 3~5분) |
| 이야기 장면(`stage`) | 전체의 12% 이상 (EP.13은 74개 중 14개) |

길이를 채우려고 같은 말을 반복하지 않습니다. 길이가 모자라면 아래 '재료'에서 **새 내용**을 더합니다.

#### 4-2. 뼈대

```
인트로 (약 2분)   ① 제목 A의 질문 장면  ② 제목 B의 질문 장면  ③ 제목 C의 질문 장면
                 ④ 세 질문 정리 + "이 영상은 전망하지 않습니다"   ⑤ 제목 장면(채널 인사)   ⑥ 오늘의 순서
PART 1 ~ 7       파트 카드 → [이야기 장면 → 정보 장면 2~3개] 반복 → 파트 요약(도장)
정리              파트 카드 → 처음 세 질문의 답 → 5줄 요약 → 아웃트로
```

- **삼중 약속 인트로**: 제목 A·B·C 어느 것을 보고 들어왔든 1분 안에 "내가 누른 이야기가 나온다"는 것을 알게 합니다. 질문 장면 3개가 제목 장면보다 **앞**에 옵니다.
- 채널 인사와 끝인사는 틀에 있는 문장을 그대로 씁니다("911"의 발음 때문에 `say` 가 따로 있습니다).
- 아웃트로 네 줄: 다음 편 예고 → 숫자의 기준일 + "투자 권유나 전망이 아닙니다" → 구독·댓글 부탁 → 끝인사.

#### 4-3. 한 파트의 흐름

`이야기 장면(왜 궁금한가)` → `뜻(큰 글자)` → `원리(흐름도)` → `숫자·비교` → `흔한 오해` → `이야기 장면(비유)` → `사례` → `파트 요약(도장)`

같은 그림 종류를 연달아 쓰지 않고, 정보 장면이 7개 넘게 이어지지 않게 사이에 이야기 장면을 넣습니다.

#### 4-5. 말투와 표현

- 존댓말(~습니다, ~예요)을 섞어 편하게. 한 문장에 한 가지 생각.
- 어려운 낱말은 처음 나올 때 바로 풀이합니다("준비금, 그러니까 은행이 중앙은행에 맡겨 둔 돈").
- 숫자에는 언제·누구 발표인지 붙입니다. ⚠️ 항목은 "약", "~로 알려져 있습니다".
- **앞날을 단정하지 않습니다.** "오를 겁니다" ✕ → "방향은 여러 요인이 섞여 정해집니다. 이 영상은 전망하지 않습니다" ○
- **권하지 않습니다.** "사세요/파세요/추천합니다" ✕ → "점검해 보세요", "계산해 두세요", "기록해 두세요" ○
- 정치적 평가를 하지 않습니다. 정책은 사실과 양쪽 주장만.
- 캐릭터는 전문가인 척하지 않습니다("10년 차 애널리스트" 같은 말 금지).
- 화면에 나올 낱말을 내레이션에도 그대로 씁니다(등장 시점을 그 낱말에 맞추기 때문).

#### 4-6. 화면 연출 규칙

- **모든 요소는 그 말이 나오는 순간에 등장**합니다. 등장 시점은 `"@줄번호:낱말"` 로 씁니다(줄 번호는 0부터, 낱말은 그 줄에 실제로 있는 것).
  - 예: `"at": "@1:금리"` = 두 번째 줄에서 '금리'라는 말이 나올 때.
  - 물결표가 든 문장은 화면 글자가 `–` 로 바뀌므로 낱말도 `–` 로 씁니다(`"@0:1–2년"`).
  - 숫자로 직접 쓰지 않습니다(줄 수보다 큰 숫자를 써서 요소가 안 나온 사고가 있었습니다).
- 18초 넘는 장면은 화면 변화가 2번 이상 있어야 합니다(요소를 나눠서 등장).
- 캐릭터 자리: 넓은 그림(compare·timeline·bars·line·ticker·balance)은 `corner`, 나머지는 `left` 와 `right` 를 번갈아. 이야기 장면은 `stage()` 가 알아서 합니다.
- 표정(`emotion`)과 태블릿 화면(`screen`)을 내용에 맞춥니다(놀라운 숫자 → surprised·shock, 걱정되는 내용 → worried, 정리 → happy).
- 큰 숫자가 찍히는 순간에만 `shake_at` 을 씁니다(한 편에 몇 번).
- 화면 글자는 짧게. 권장 글자 수:

| 자리 | 한도 | 자리 | 한도 |
|---|---|---|---|
| 파트 제목 | 16자 | 도장(`stamp`) | 8자 |
| 말풍선·큰 한마디 | 18자 | 연표 `label` / `sub` | 15자 / 18자 |
| 소품 글자 | 10자 | 아이콘 카드 `text` / `sub` | 20자 / 24자 |
| 시세판 이름 | 18자 | 막대 이름 | 22자 |

- 장소 배경(`META["envs"]`)은 파트 순서대로 바뀝니다. 내용에 맞게 고릅니다(은행 이야기 → bank, 생활 → home·market, 역사·공부 → study, 마무리 → night).
- 그림 종류별 옵션과 예시는 [`VISUALS.md`](VISUALS.md), 실제 쓴 예시는 `python -m studio.ep example <종류>`.

## 3. 바꾸지 않는 규칙

1. **사실**: 확인된 숫자만. 기준일 명시. 출처를 설명란에. ⚠️는 완충.
2. **전망·권유 금지**: 시장·정책의 앞날을 말하지 않고, 사라/팔라고 하지 않습니다. 영상 안에 "전망하지 않습니다"를 2번 이상.
3. **자극 금지**: 공포 예고, 과장, 낚시 제목을 쓰지 않습니다. 제목의 약속은 영상에서 지킵니다.
4. **AI 사용 고지**: 설명란에 AI 도움과 AI 음성 사용을 밝힙니다(자동으로 들어갑니다). 캐릭터는 실존 인물이 아닌 마스코트.
5. **남의 것 금지**: 남의 영상·대본·그림·사진·로고를 쓰지 않습니다. 벤치마크는 공개 숫자와 구성 원칙만.
6. **편마다 다르게**: 같은 틀에 낱말만 바꾼 영상을 만들지 않습니다. 줄거리·구성·그림을 주제에 맞게 새로 짭니다(유튜브의 '대량 생산 콘텐츠' 정책, [`02_youtube_policy_2026.md`](02_youtube_policy_2026.md)).
7. **비밀**: API 키를 화면에 출력하거나 대화에 적거나 커밋하지 않습니다. 채널 주인의 이메일 등 개인 정보를 바깥 서비스에 보내지 않습니다.
8. **저장소 글**: 저장소 파일(코드·문서·주석)에는 특정 AI 모델의 이름을 적지 않습니다.
9. **되돌릴 수 없는 일은 먼저 묻기**: 이미 올린 편을 다시 만들기, 풀 리퀘스트, 예약 작업 켜기, 바깥에 게시하기.

## 4. 채널 주인의 선호 (지금까지 들은 말)

- 영상은 **30분 정도**, 길수록 좋다. 단, 진짜 내용으로.
- 사실은 **미리 확인**해서 만든다.
- 제목 A/B/C는 **정말로 다른 각도**, 썸네일은 **한눈에 들어오게**, 편마다 다양하게.
- **삼중 약속 인트로** 유지.
- 보고는 쉬운 말로, 끝나면 **파일을 보내 준다**. 진행 상황을 자주 보내지 않는다.
- 사용량(비용)에 민감하다: 불필요한 재렌더링, 보조 작업자 여러 개 띄우기, 매일 도는 예약 작업은 요청이 있을 때만.
- 업로드는 채널 주인이 직접 한다(하루 한 편쯤). 자료는 업로드 센터(아티팩트)에서 본다.
- 목표는 **수익 창출**. 다만 결과를 장담하지 않고 사실대로 말해 주길 원한다.

## 5. 자주 겪는 문제

| 증상 | 원인과 해결 |
|---|---|
| `등장 시점 키워드를 찾지 못했습니다` | `@줄:낱말` 의 낱말이 그 줄에 없음. 줄 번호(0부터)와 낱말을 실제 문장에 맞춤. 물결표 문장은 `–` 로 |
| 요소가 화면에 안 나옴 | 등장 시점이 줄 수보다 큼 → `@줄:낱말` 로 다시. `check` 의 `at-range` 오류 |
| 화면 글자가 색으로 바뀌거나 사라짐 | `*노랑*` `^빨강^` `~초록~` `` `파랑` `` 이 색 기호. 물결표는 `–` 로(`add()` 가 자동 처리) |
| 글자가 겹치거나 잘림 | 글자 수를 줄이거나 항목 수를 줄임(연표 5개, 도장 5줄, 아이콘 카드 6개, 소품 3개까지). 긴 제목은 자동으로 작아짐 |
| 제목의 분과 실제 길이가 다름 | 숫자를 직접 쓰지 말고 `{MIN}` 을 쓴 뒤 `ep script` |
| 음성 합성 실패 | 네트워크 문제. 다시 실행하면 이미 만든 문장은 캐시를 씀 |
| 파일이 400MB를 넘어 못 보냄 | `ep verify` 가 `video_send.mp4` 를 만듦 |
| 디스크가 부족함 | `cache/chunks`, 오래된 편의 `out/video.mp4`·`video_send.mp4` 를 지움(채널 주인에게 이미 보낸 것만) |
| 새 작업 공간에 예전 영상 파일이 없음 | 정상. 영상은 저장소에 올리지 않음. 필요하면 `ep render` 로 다시 만들 수 있음(대본이 그대로면 같은 영상) |
| `ep new` 가 "이미 있습니다" | 그 번호의 폴더가 있음. `ep status` 로 다음 번호 확인 |
| 조회 도구가 "API 키가 없습니다" | 1장의 3번 참고. 키 없이도 제작은 가능 |
| 썸네일 화면 채움 경고 | 참고용 수치. 작게 봐도 읽히면 그대로 둠(EP.13도 같은 경고가 있었음) |

## 7. 수익 창출까지 남은 일 (사실대로)

- 조건: 구독자 1,000명 + 최근 365일 공개 시청 4,000시간. 2027년 2월 1일부터 새로 신청하는 채널은 8,000시간으로 오른다는 보도가 있습니다(공식 확인 필요, [`02_youtube_policy_2026.md`](02_youtube_policy_2026.md)).
- 지금 위치와 벤치마크는 [`04_benchmark.md`](04_benchmark.md), 최신 숫자는 [`STATUS.md`](STATUS.md).
- 신청 전에 해결할 것:
  1. **목소리**: 지금 쓰는 무료 AI 음성(edge-tts)은 공식 상업용 사용권이 아닙니다. 수익 신청 전에 본인 녹음(`episodes/<편>/voice/`에 문장별 파일을 넣으면 그 목소리로 만들어짐, `README.md`) 또는 사용권이 분명한 음성으로 바꾸는 것을 권합니다.
  2. **대량 생산 콘텐츠 정책**: 비슷한 틀의 AI 영상을 많이 올리면 수익 창출이 거절될 수 있습니다. 편마다 줄거리·구성이 달라야 하고, 사실 확인·출처·고지를 유지합니다.
